# Design notes

Context on the visual direction, for consistency if extending the site further.

## Background: two design passes happened this session

**Pass 1 (discarded):** Before the user uploaded their Lovable export, Claude built a from-scratch static HTML/CSS/JS homepage mockup for "Detailed By Nate" to demonstrate a design direction — dark obsidian/charcoal palette, candy-apple red accent, condensed uppercase display type (Oswald) paired with monospace stat/price treatment (IBM Plex Mono), a "gloss sweep" light-reflection animation as the signature element, and a garage-service-ticket motif for the process steps. This was explicitly framed as a first pass to validate direction before committing to a real framework build.

**This mockup is not part of the current codebase** — the user then uploaded an existing Lovable-built site ("Glow and Go Detailing" / "Nate's Shine Studio") and asked Claude to use that instead. The current repo is 100% the Lovable export plus Claude's backend additions. If you encounter any reference to the standalone HTML mockup elsewhere (e.g. old chat history), it's not relevant to this repo.

## Pass 2 (current, in this repo): the Lovable-authored design

The actual site (`src/routes/index.tsx`, `book.tsx`, `results.tsx`) was originally generated by Lovable from this prompt (verbatim, from the original `README.md`):

> "Build me a modern car detailing website with a book now button and fluid animations and everything, make it a darker website but have glow and stuff the name of the company is Detailed by Nate add the effect where numbers gradually go up and it says 150+ clients served also add a 5 star review thing and a section where i can add the reviews and have it has an animation add sample text inside the review boxes. also add a faq at the bottom."

Resulting direction, already implemented in the scaffold — **follow this for consistency, don't reintroduce Pass 1's palette/type choices**:

- Dark theme with a primary-color glow/gradient treatment (`.glow-text`, `primary-glow` gradient stops used throughout).
- `.glass` utility class for translucent card surfaces (used for nav, CTA panels, FAQ container, the booking widget).
- Count-up number animations via `motion`'s `useMotionValue`/`animate` (see the `Counter` component duplicated in both `index.tsx` and `results.tsx` — could be extracted to a shared component if touched again).
- Package tiers: **Diamond** (interior+exterior, "the full obsession"), **Gold** (interior only), **Silver** (exterior only) — copy and features already written in `index.tsx`'s `services` array. `src/lib/services.ts` (the backend's service catalog) mirrors these three tiers by id/price/duration but is a separate list — see `docs/booking-system.md` "Known gaps."
- Reviews section with 5-star ratings and named reviewer + car model pairs — sample copy already written in `index.tsx`'s `reviews` array.
- FAQ section at the bottom (accordion, shadcn `accordion.tsx`).
- Font stack: whatever's set as `font-display`/`font-helvetica`/`font-primary` custom Tailwind classes in the existing scaffold's CSS — check `src/styles.css` rather than assuming; do not introduce Oswald/IBM Plex Mono (that was the discarded Pass 1 identity).

## `BookingWidget.tsx` styling choices

Built to visually match the existing `.glass`/`primary`/`primary-glow` system rather than introducing new tokens — package cards, date chips, and time-slot buttons all use `border-primary`/`bg-primary/10` selected-state treatment consistent with the rest of the site. If the overall theme's CSS variables change, this component should pick it up automatically since it uses the same Tailwind/shadcn classes, not hardcoded colors.

## If doing more design work later

Re-read the actual current CSS (`src/styles.css`, Tailwind v4 config-in-CSS) and the existing pages before adding new visual patterns — don't assume Pass 1's design-brainstorm output above applies here; it explicitly doesn't. The goal for any new page/section is to extend what Lovable + this session already established, not introduce a third identity.
